# Plan: Telegram Sync Optimization

## 1. 문제 분석 (Problem Analysis)
- **채널 수집 편중**: 현재 `sync_history.py`는 채널을 순차적으로 처리하며, 한 채널의 모든 히스토리를 다 가져올 때까지 다음 채널로 넘어가지 않음.
- **주요 채널 정체**: 메시지 양이 많은 채널(예: gaoshoukorea)에서 시간이 너무 오래 걸려 GitHub Action 타임아웃(6시간) 내에 다른 채널을 처리하지 못함.
- **메시지 순서 오류**: 사용자가 2020년 -> 2019년 순서로 메시지가 온다고 보고함. 이는 현재 코드의 `reverse=True` 로직이 의도와 다르거나, 혹은 너무 최근 데이터부터 역순으로 가져오고 있을 가능성이 있음.
- **중단 현상**: 대량의 메시지 처리 중 오류가 발생하거나 타임아웃으로 인해 작업이 중단됨.

## 2. 목표 (Goals)
- **라운드 로빈(Round-robin) 방식 도입**: 각 채널별로 일정량(예: 100개)씩 번갈아가며 수집하여 모든 채널이 골고루 업데이트되도록 개선.
- **날짜 필터링 강화**: 특정 연도(예: 2021-2025) 제외 및 수집 시작/종료 날짜 설정을 명확히 처리.
- **수집 방향 최적화**: 과거 데이터부터 현재로 올지(Oldest to Newest), 혹은 최신부터 과거로 갈지(Newest to Oldest) 사용자 옵션 제공 및 정확한 구현.
- **체크포인트 안정성**: 채널별 마지막 처리 ID를 안전하게 저장하고, 중단 시 해당 지점부터 재개.

## 3. 해결 방안 (Proposed Solutions)
- **Sync Logic 개편**:
    - `sync_history.py`를 라운드 로빈 방식으로 수정.
    - `channels.json`에 `sync_settings` 추가 (batch_size, direction 등).
- **성능 최적화**:
    - 불필요한 `sleep` 조정 및 FloodWait 예외 처리 강화.
    - 미디어 전송 실패 시 텍스트만 전송하는 로직 안정화.
- **날짜 제어**:
    - `exclude_years` 또는 `start_date`, `end_date`를 `channels.json`에서 직접 관리하도록 UI/Config 개선.

## 4. 단계별 계획 (Step-by-step Plan)
1. **분석**: 현재 `sync_history.py`와 `channels.json` 인터페이스 분석 (완료).
2. **설계**: 라운드 로빈 방식의 루프 구조 및 체크포인트 확장 설계.
3. **구현**:
    - `sync_history_optimized.py` (또는 기존 파일 수정) 구현.
    - 날짜 필터링 로직 추가.
4. **검증**: 소량의 데이터로 라운드 로빈 및 날짜 필터링 작동 확인.
5. **보고**: 최적화 결과 보고.
