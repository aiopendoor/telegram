# Analysis: Telegram Sync Optimization

## 1. 최적화 결과 요약 (Optimization Summary)
- **라운드 로빈 수집 도입**: 한 채널에 정체되지 않고 모든 채널을 균등하게(배치 단위) 업데이트하도록 개선하였습니다.
- **날짜 필터링 고도화**: `exclude_years` 설정을 통해 2021-2025년과 같은 불필요한 구간을 효율적으로 건너뛸 수 있게 하였습니다.
- **체크포인트 안정성**: 메시지 전송 직후 및 라운드 종료 시 체크포인트를 저장하여 중단 시 재개가 확실하도록 개선하였습니다.
- **오류 처리 강화**: 사라진 채널이나 접근 불가 채널로 인해 전체 프로세스가 멈추는 문제를 해결하였습니다.

## 2. 주요 수정 내역 (Key Changes)

### `sync_history.py`
- 기존의 중첩 루프(채널 -> 메시지 전체)를 라운드 로빈 루프(무한 반복 -> 채널 -> 메시지 배치)로 변경.
- `process_message` 함수를 분리하여 전송 로직(FloodWait 대응, 미디어 처리)을 캡슐화.
- 제외 대상 연도(`exclude_years`) 처리 시 전송은 하지 않지만 `last_id`는 업데이트하여 다음 실행 시 다시 검사하지 않도록 함.

### `channels.json`
- `history_settings` 섹션을 추가하여 수집 시작일, 제외 연도, 배치 크기를 사용자가 제어할 수 있도록 함.

## 3. 사용자 이슈 대응 (User Issue Resolution)
- **"gasoshoukorea 채널에서만 메시지가 온다"**: 라운드 로빈 도입으로 해결. 이제 모든 채널이 배치 단위로 번갈아가며 수집됩니다.
- **"2020년 후 다시 2019년이 온다"**: 채널별로 시점이 다르기 때문에 발생하는 현상입니다. 라운드 로빈으로 모든 채널이 함께 전진하므로 시점 차이가 줄어들고, `reverse=True`를 통해 각 채널 내에서는 시간 순서가 보장됩니다.
- **"중단되어 있다"**: GitHub Action의 타임아웃이나 체크포인트 미저장 문제일 가능성이 큽니다. 배치 단위를 조정하고 효율적인 스킵 로직을 추가하여 타임아웃 전에 최대한 많은 채널을 처리하도록 하였습니다.

## 4. 향후 권장 사항
- 메시지 양이 매우 많을 경우 GitHub Action 실행 주기를 짧게 하거나, 수동 실행 시 `batch_size_per_channel`을 조정하여 조금씩 자주 업데이트하는 것이 좋습니다.
