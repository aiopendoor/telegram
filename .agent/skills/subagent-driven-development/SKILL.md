# 서브 에이전트 기반 개발 (Subagent-Driven Development)

각 작업당 신규 서브 에이전트를 할당하여 계획을 실행하며, 각 작업 후에는 두 단계 리뷰(스펙 준수 리뷰 우선, 그 다음 코드 품질 리뷰)를 거칩니다.

**핵심 원칙:** 작업당 신규 서브 에이전트 + 2단계 리뷰 (스펙 그 다음 품질) = 고품질, 빠른 반복

## 사용 시점

구현 계획이 있고, 작업들이 대부분 독립적이며, 현재 세션 내에서 머물고 싶을 때 사용합니다.

**vs. 계획 실행 (executing-plans - 병렬 세션):**
- 동일 세션 유지 (컨텍스트 전환 없음)
- 작업당 신규 서브 에이전트 (컨텍스트 오염 방지)
- 각 작업 후 2단계 리뷰: 스펙 준수 여부 확인 후 코드 품질 확인
- 더 빠른 반복 (작업 간 인간의 개입 최소화)

## 프로세스 (The Process)

1. **계획 읽기**: 전체 작업을 추출하고 컨텍스트를 파악합니다.
2. **구현 에이전트 할당**: 각 작업을 위해 신규 서브 에이전트를 생성합니다.
3. **리뷰 루프**:
   - **스펙 리뷰 에이전트**: 구현된 코드가 요구사항(스펙)과 일치하는지 확인합니다.
   - **코드 품질 리뷰 에이전트**: 코드 스타일, 성능, 가독성 등 품질을 확인합니다.
4. **작업 완료 및 반복**: 모든 이슈가 해결되면 작업을 완료로 표시하고 다음 작업으로 넘어갑니다.
5. **최종 리뷰**: 모든 작업 완료 후 전체 구현에 대한 최종 리뷰를 진행합니다.

## 장점

- **수동 실행 대비**: 서브 에이전트가 자연스럽게 TDD를 따르며, 작업별로 신선한 컨텍스트를 유지합니다.
- **계획 실행 대비**: 동일 세션 내에서 연속적인 진행이 가능하며 리뷰 체크포인트가 자동화됩니다.
- **품질 게이트**: 셀프 리뷰, 스펙 리뷰, 품질 리뷰의 다중 단계를 통해 오류를 사전에 차단합니다.

## 금지 사항 (Red Flags)

- 리뷰(스펙 또는 품질)를 생략하지 마십시오.
- 해결되지 않은 이슈가 있는 상태로 다음 작업을 진행하지 마십시오.
- 여러 구현 서브 에이전트를 동시에 할당하지 마십시오 (충돌 위험).
- 서브 에이전트의 질문을 무시하지 말고 명확하게 답변하십시오.
- **스펙 준수 확인(✅) 전에는 코드 품질 리뷰를 시작하지 마십시오.** (순서 중요)

## 관련 스킬

- **writing-plans**: 이 스킬이 실행할 계획을 생성합니다.
- **test-driven-development**: 서브 에이전트가 각 작업을 수행할 때 TDD를 따르도록 합니다.
- **finishing-a-development-branch**: 모든 작업 완료 후 개발을 마무리합니다.
